# workplace-reply

这是一个帮助处理职场沟通的 Codex Skill，用来把不完整、口语化、带风险的聊天或邮件内容，整理成可以直接发送的回复。

## 适用场景

这个 skill 适合用于：

- 回复领导、同事、客户、供应商
- 拒绝不合适的请求
- 催办进度
- 解释情况或澄清误会
- 确认边界、条件和责任
- 避免在未确认时承诺数量、价格、时间、结果
- 根据用户习惯持续调整回复风格

## 核心目标

这个 skill 的目标不是"写得更像模板"，而是：

- 帮用户先抓住对方真正想要什么
- 避免在沟通中无意承诺
- 避免把"收到""了解"写成"同意"
- 避免编造理由、扩大责任或暴露底牌
- 给出简短、自然、可直接发送的回复

## 工作原则

- 优先保护用户的真实利益
- 不替用户编造事实
- 不把未确认内容写成确定结论
- 不替用户做未授权承诺
- 不把正常沟通写成过度正式、空泛或像模板的表达
- 能短就短，但不能删掉必要边界

## 输出方式

默认会给出：

1. 一段可直接发送的回复
2. 简短说明这段话保留了什么边界
3. 必要时给出更客气版或更坚定版

## 常见能力

- 识别对方的真实诉求
- 判断沟通中的风险点
- 针对不同对象生成合适回复
- 根据用户反馈调整表达习惯
- 维护长期可复用的个人沟通规则

## 个人规则

如果用户明确表示：

- 以后都这样
- 加入规则
- 记住这个
- 以后统一按这个来

则可以把稳定且可复用的偏好沉淀到个人规则文件中。

但如果只是一次性的修改，或者边界不清晰，就不要写入长期规则。

## 建议使用方式

当用户发来聊天、邮件、截图，或者想先打磨措辞时，可以直接说：

- 帮我直接写一版回复
- 帮我判断这句话有没有风险
- 帮我写得更客气一点
- 帮我拒绝但别太硬
- 帮我确认边界，但不要显得太强势

## 说明

这个 skill 会优先给出能直接发送的文本，而不是长篇分析。
如果信息不够，会只问真正影响回复结果的少量关键问题。
