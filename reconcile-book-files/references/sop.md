# 书籍 CSV 与实际文件一一对应整理 SOP

> 版本：1.0  
> 更新日期：2026-08-04  
> 用途：批量整理书籍 CSV、规范书名/作者/出版社、补充 ISBN，并同步重命名实际书籍文件。

## 1. 文档目标

本 SOP 用于解决以下问题：

1. CSV 中的书名、作者、出版社存在编号、书名号、拼音、重复姓名、地址前缀或其他噪声。
2. CSV 的书籍名称与实际 PDF、EPUB 等文件名不能直接对应。
3. 同名书籍需要通过出版社和 ISBN 进一步区分。
4. 文件名可能正确、部分正确、完全错误，必须依据封面、版权页和正文判断。
5. 最终必须做到：CSV 中每条“书籍名称”唯一对应一个实际文件，实际文件也唯一对应一条 CSV 记录。

这不是单纯的文本清洗任务，而是“书目数据清洗 + 实际文件核验 + 文件迁移 + 一致性验收”任务。

## 2. 不可变原则

1. 以 CSV 的“书籍名称”列作为匹配入口。
2. 必须检查文件夹中的实际文件名，禁止用 `dst_path`、`tos_path` 或其他路径字段代替实际文件判断。
3. 原始 CSV 不覆盖、不改名、不删除，开始前和完成后均计算 SHA-256。
4. 只允许修改已授权字段。默认允许修改：
   - 书籍名称
   - 作者
   - 出版社
   - ISBN（允许新增）
5. 除授权字段外，其他列的行数、顺序、内容和空值状态必须保持不变。
6. 不确定的信息不能猜测。查不到时保留原值或留空，并写入异常报告。
7. 所有文件重命名必须先生成预览清单，确认无冲突后再执行。
8. 完成后必须重新读取实际目录和最终 CSV 做独立验收，不能只相信处理脚本的预期结果。

## 4. 字段清理规则

### 4.1 书籍名称

必须执行：

- 删除书名号、等于号、无意义引号、无意义括号及重复空格。
- 删除文件扩展名残留，例如 `.pdf.pdf`、`.zip`、`.doc`。
- 删除前置流水号、ISBN 前缀、下载编号、页数后缀等非书名内容。
- 删除重复拼音，但不能删除原生英文书名。
- 保留上、中、下、第一册、卷一、I、II、版本号、年份等核心标识。
- 中文原著保留中文书名，英文原著保留原生英文书名。
- 中英文并列确属正式题名时可以同时保留。
- “精装”“平装”“附光盘”等包装信息通常删除，除非它是版本识别所必需的信息。

不能只依据 CSV 文本清洗的场景：

- CSV 书名与封面卷次不一致。
- 文件名是新闻标题、软件默认名或 `Microsoft Word` 占位名。
- 文件名只有 ISBN、出版社、编号或扫描批次号。
- 同一个文件名可能对应多个不同版本。

这些场景必须查看封面、扉页、版权页或正文。

### 4.2 作者

必须执行：

- 删除重复姓名，同一责任者只保留一次。
- 删除拼音重复、出生年份、网页地址、软件名称、扫描工具信息等噪声。
- 保留作者原有国家/地区标识，例如 `(美)`、`(日)`、`(韩)`。
- 保留责任角色，例如 `著`、`编著`、`主编`、`副主编`、`译`、`摄影`、`策划`。
- 多位责任者使用统一分隔方式，建议使用中文顿号。
- 出版社或机构确实作为编者时必须保留，不能因为名称中含“出版社”就删除。
- 不得把主编、译者和作者混为同一角色。

作者清理完成后重点检查：

- `主编张三、李四主编` 这类角色前后重复。
- `韩国某出版社编、(韩)某出版社编` 这类同一机构重复。
- 姓名相似但实际是不同人的情况，不能仅按包含关系删除。

### 4.3 出版社

必须执行：

- 删除城市和地址前缀，例如 `北京：`、`上海:`、`地址：`。
- 删除邮编、电话、网址、发行地址等信息。
- 保留完整出版社主体名称。
- 避免只剩“大学出版社”“科技出版社”等无归属名称。
- 出版社发生更名时，以书籍版权页所载版本为准，不自动替换为当前名称。
- 多个联合出版单位确实同时出现时可保留，并使用统一分隔符。

### 4.4 ISBN

- 统一保存为不含连字符的 13 位 ISBN。
- 写入前必须验证 ISBN-13 校验位。
- 不能用相似书名、相邻年份或其他版本的 ISBN 代填。
- 套装 ISBN、单册 ISBN 和上下册共同 ISBN 必须依据版权页或可靠检索结果判断。
- 查不到时留空或保留原值，并在报告中注明查询过程和结果。

## 5. 文件命名规则

“书籍名称”列最终保存的是文件名去掉扩展名后的完整 stem，因此必须与实际文件名同步。

| 场景 | 文件名格式 | CSV“书籍名称”值 |
|---|---|---|
| 书名唯一 | `书名.pdf` | `书名` |
| 书名重复、出版社不同 | `书名_出版社.pdf` | `书名_出版社` |
| 书名和出版社均相同 | `书名_出版社_ISBN.pdf` | `书名_出版社_ISBN` |
| 书名、出版社、ISBN 均相同，但确有多份不同扫描 | `书名_出版社_ISBN_1.pdf`、`..._2.pdf` | 同步保留 `_1`、`_2` |

最后一种情况属于保证一一对应的技术性例外，必须在报告中说明这些文件是同一本书的不同扫描件。

文件名还必须满足：

- 同一目录内大小写不敏感时也不能冲突。
- 不包含 `/`、`NUL`、冒号等文件系统非法字符。
- 需要保留扩展名原格式，例如 PDF 仍为 `.pdf`，EPUB 仍为 `.epub`。
- 若同时保留 AppleDouble sidecar，目标文件名建议控制在 253 个 UTF-8 字节以内，为 `._` 前缀预留空间。

## 6. 匹配与证据等级

匹配时按照以下证据逐级判断：

### A 级：直接书籍证据

- 封面
- 扉页
- 版权页/CIP
- ISBN 条码
- 正文标题或目录

### B 级：文件结构证据

- 实际文件名
- 文件页数
- PDF 元数据
- 同批次文件关系

### C 级：外部检索证据

- 出版社官方网站
- 图书馆馆藏信息
- 正规图书销售页面
- 多个相互独立且信息一致的书目页面

### D 级：无法确认

以下情况必须进入异常报告：

- 文件缺封面和版权页。
- 文件损坏或页面无法读取。
- 浏览器检索没有可靠结果。
- 多个版本书名相同，但无法判断当前扫描件属于哪一版。
- CSV 值和文件内容均不能形成可靠证据链。

## 7. 标准执行流程

### 阶段 0：冻结需求

开始前确认：

- 输入路径和输出路径。
- 允许修改的列。
- 文件命名层级。
- 是否保留和同步处理 `._` 文件。
- ISBN 查询触发条件。
- 无法确认时保留还是留空。

冻结后不在处理中临时改变命名规则。

### 阶段 1：只读盘点

此阶段禁止改名和写回原 CSV。

检查内容：

1. CSV 编码、表头、行数和列数。
2. 文件夹内可见书籍数量。
3. `._` 隐藏元数据数量。
4. 子文件夹数量。
5. PDF、EPUB 和其他格式数量。
6. CSV 原文件 SHA-256。
7. 是否有大小写或 Unicode 规范化冲突。
8. 在正式批量操作前，用一个可回滚样本测试外置卷的 `._` 重命名行为。

注意：书籍数量默认不包含以 `._` 开头的 AppleDouble 文件。

### 阶段 2：建立 CSV 与实际文件映射

1. 从 CSV“书籍名称”生成规范化匹配键。
2. 从实际文件名生成规范化匹配键。
3. 优先匹配书名，再使用页数、出版社和封面缩小候选范围。
4. 每条 CSV 只能匹配一个实际文件。
5. 每个实际文件只能被一条 CSV 使用。
6. 输出缺失文件、多余文件、低置信度匹配和候选冲突。

禁止事项：

- 不得以 `dst_path` 相同为由认定实际文件匹配。
- 不得仅因为页数相同就认定是同一本书。
- 不得在映射尚未唯一时开始批量重命名。

### 阶段 3：批量清理普通记录

先应用稳定的通用规则：

- 标点和空格清理。
- 扩展名和编号清理。
- 拼音重复清理。
- 作者去重和角色规范。
- 出版社地址前缀清理。

这一阶段只处理高置信度记录，疑难记录进入异常队列。

### 阶段 4：核验异常记录

异常记录优先检查前 3 至 10 页：

1. 封面确认书名和卷次。
2. 扉页确认责任者。
3. 版权页确认作者、出版社和 ISBN。
4. 文件名明显错误时检查正文和目录。
5. PDF 解析失败时使用页面渲染，不因一个解析器报错就认定文件损坏。

所有人工覆盖值需要记录证据来源。

### 阶段 5：处理重复书名和 ISBN

1. 按清洗后的书名分组。
2. 同书名时比较出版社。
3. 同书名、同出版社时才触发 ISBN 查询。
4. 推荐搜索词：`书名 + 出版社 + ISBN`。
5. 查询结果必须与作者、年份或封面信息相互印证。
6. 查询不到时保留，并写入异常报告。
7. 所有 ISBN 通过校验位检查后才能写入。

### 阶段 6：生成干运行结果

在实际重命名前生成：

- 最终 CSV 预览。
- 匹配与异常报告预览。
- 重命名记录预览。
- 所有旧文件名到新文件名的映射表。

干运行必须通过：

- 目标文件名唯一。
- 无大小写冲突。
- 无非法字符。
- 无超长文件名。
- 所有源文件存在。
- 所有需要保留的 sidecar 存在。
- 所有同书名、同出版社组均已获得 ISBN，或已经明确采用保留策略。
- 最终 CSV 重新导入后行列数正确。
- 未授权列逐单元格比较结果为 0 个变化。

### 阶段 7：事务式重命名

推荐使用两阶段重命名：

1. 所有源文件先移动到唯一临时名。
2. 所有临时名再移动到最终目标名。
3. 任一步骤失败时按相反顺序回滚。
4. 输出 CSV 先写临时文件，书籍文件全部成功后再落到最终文件名。

若保留 macOS `._` 元数据：

1. 先把 sidecar 隔离为不以 `._` 开头的暂存名。
2. 再重命名可见书籍文件。
3. 将暂存 sidecar 恢复为 `._最终文件名`。
4. 重新扫描是否产生 `._._最终文件名` 嵌套副本。
5. 只有确认它们是本次新生成、正式 `._最终文件名` 仍完整存在时，才删除嵌套副本并保存删除清单。

### 阶段 8：独立验收

完成后重新从磁盘读取，不复用重命名前的目录列表。

必须检查：

- 可见书籍数量等于 CSV 数据行数。
- CSV 每个书名 stem 对应且只对应一个实际文件。
- 每个实际文件只对应一条 CSV。
- 无缺失文件、无多余文件、无临时文件。
- 无目标文件名冲突。
- 需要保留时，正式 `._` 文件数量和目标名称完全对应。
- 没有遗留 `._._` 嵌套副本。
- 最终 CSV 行列数正确。
- 非授权字段变化数量为 0。
- 原始 CSV SHA-256 未变化。
- 输出文件 SHA-256 已记录。

## 8. 核验分类

最终报告中的每条记录应归入以下一个类别：

1. `书名完全对应`
2. `书名相同但存在多个文件，需要进一步区分`
3. `文件名与 CSV 书名不对应`
4. `无法确认的异常文件`

建议报告字段：

| 字段 | 说明 |
|---|---|
| CSV 行号 | 可追溯到原始记录 |
| 核验分类 | 四类之一 |
| 原书籍名称 | 原始 CSV 值 |
| 清洗后书籍名称 | 最终文件 stem |
| 原作者/清洗后作者 | 字段变化对照 |
| 原出版社/清洗后出版社 | 字段变化对照 |
| ISBN | 最终 ISBN |
| 原文件名/新文件名 | 实际重命名记录 |
| 匹配依据 | 文件名、页数、封面、版权页、正文或浏览器检索 |
| 备注 | 异常、保留值和人工判断说明 |

## 9. 最终交付物

至少生成以下三份文件：

1. `原CSV名_规范化_日期.csv`
2. `书籍文件夹名_匹配与重命名报告_日期.csv`
3. `书籍文件夹名_重命名记录_日期.csv`

可选生成：

- ISBN 查询证据清单。
- 无法确认记录清单。
- 自动清理的临时 sidecar 清单。
- SHA-256 验收结果 JSON。

- [ ] 其他未授权列没有变化。

- [ ] 中文书名保留中文，英文书名保留原生英文。

## 11. 提速方法

1. 普通记录和异常记录分流，批量规则只处理高置信度记录。
2. 页数、封面、版权页和查询结果全部缓存，避免重复读取。
3. 只为同书名、同出版社冲突组查询 ISBN。
4. 浏览器查询设置单次超时，失败后切换可靠来源。
5. 建立出版社规范名称字典和作者噪声词典。
6. 保留约 30 条典型脏数据作为“黄金测试集”。
7. 每次任务结束后，把人工确认结果转成规则或例外表。
8. 在批量重命名前先测试外置卷及 `._` 文件行为。

## 13. 本次执行经验

本 SOP 首次来源于 1392 条书籍记录的完整整理任务，实际遇到的典型异常包括：

- 文件夹中同时存在 1392 个书籍文件和 1392 个 `._` 元数据文件。
- 文件名是新闻标题或软件默认占位名，但正文实际是另一部书。
- PDF 解析器报错，但文件仍可用其他工具读取和渲染。
- 作者字段包含拼音、出生年份、软件信息及重复责任者。
- 出版社字段包含城市、地址或错误数字。
- 同一书名、出版社和 ISBN 存在多份不同扫描件。
- macOS 在外置卷上重命名时产生 `._._` 嵌套元数据副本。

这些异常不应通过猜测解决，应通过证据分级、例外记录、事务式执行和最终独立验收解决。
